# 화재 피해자용 공공 웹앱 — "단계 진행감" UI 리서치

참고자료 — 확정 아님. 확정 설계는 doc/design-decisions.md D-019.

## TL;DR
- **진행감은 "조용한 상태 표시"로 만들어야 한다.** 검증된 최적 패턴은 GOV.UK/HMRC의 "색 없이 텍스트 라벨만 쓰는 태스크 리스트"(완료/잠김/기다리는 중) + CJ대한통운식 "이벤트가 쌓이는 세로 타임라인" + USCIS식 "예상 소요기간을 병기한 마일스톤 로그"의 결합이다. 게임화·거짓 진행률·속도 약속은 전부 배제한다.
- **가장 답답한 "긴 대기"는 정체가 아니라 진행으로 표현하되, 사실만 쓴다.** 확인 결과 실제로 오래 걸리는 것은 "서류 발급"이 아니라 "화재조사 완료"다(정부24 발급 자체는 "즉시 3시간"). 따라서 "화재조사 진행 중 · 완료되면 화재증명원 발급"이 정확하며, 진행률 %는 금지(CERC "under promise").
- **확정 골격과 부딪히는 근거가 5건 있다.** 특히 (a) 종착점 "회복"을 고정점으로 그리는 것은 FEMA·CERC의 "회복은 점진적, 결과를 약속하지 말라"와 충돌하고, (b) 급성 스트레스의 작업기억 손상 연구(Shields 2016)에 비추면 "카드 5장 동시 노출"은 많다. 대안을 각 항목에 제시했다.

---

## Key Findings
1. **가장 안전하고 검증된 상태 표시는 "색이 아니라 글자"다.** HMRC는 상태 태그에서 색 배경을 걷어내고 텍스트 라벨만 남긴 버전이 사용성 테스트에서 더 잘 이해됐다고 보고했다. 이는 정신없는 사용자·색각이상·저시력을 동시에 만족시키며 WCAG 1.4.1과도 정합한다.
2. **긴 대기를 진행으로 느끼게 하는 핵심은 "명시적 상태 + 예상기간 병기"다.** USCIS의 "Received"는 수주~수개월 지속돼 사용자가 침묵을 정체로 오해하는데, 이 고통 구조가 우리 서비스의 화재조사 대기와 동일하다. 해법은 상태에 소요기간 범위를 반드시 붙이는 것.
3. **게임화는 전면 안티패턴이다.** 스트릭·배지·완료 축하(폭죽, Domino's "mmm!")는 재난 맥락에서 죄책감·압박을 유발한다. goal-gradient(진행 가시화)는 동기를 올리지만 동시에 완료 압박도 만든다는 연구가 있어, "진행감은 주되 압박은 배제"라는 제약의 학술적 경계선이 된다.
4. **"진정 색상(calming colors)" 주장은 근거가 약하다.** 색으로 감정을 유도하려 하지 말고 색은 대비·가독성·상태 구분에만 써야 한다.
5. **확정 문구 "불이 꺼졌듯, 이 시간도 지나갑니다."는 유지 가능하다.** 진행률을 약속하지 않고 은유가 부드러워 다크패턴·거짓 진행률에 해당하지 않는다. 반면 가로 암시선의 종착점 "회복"과 카드 5장 규칙은 재검토가 필요하다.

## Details

### 0. 배경 (이 문서만 읽어도 되게)

**서비스 맥락.** 집에 불이 난 직후의 사람이 쓰는 공공 웹앱이다. 화재조사관이 현장에서 건네는 QR로 진입하므로 사용자는 거의 전부 휴대폰으로 열고, 정신이 없고 길게 읽을 수 없다. 설문에 답하면 개인 상황·경과 시간에 맞는 "지금 할 일 / 하지 말 일" 타임라인이 나온다. 회복 여정에는 긴 기다림이 있고, 그 대기가 사용자의 가장 답답한 구간이다. 목표 감정은 하나 — "한 단계씩 잘 밟아가고 있고, 회복에 가까워지고 있다."

**서류 발급 실제 절차.** 화재 사실 증명 서류는 「화재증명원」이며 근거는 「소방의 화재조사에 관한 법률」 제16조·시행규칙 제9조다(law.go.kr, nfds.go.kr). 정부24 기준 행정 처리기간은 "즉시(근무시간 내 3시간)", 수수료·구비서류 없음으로 명시돼 있다 — **단 이는 화재조사가 이미 완료된 경우다.** 조사가 진행 중이면 피해액 등이 "조사중"으로 기재돼 발급된다(화재조사 및 보고규정 제52조). 소방대가 출동하지 않은 화재는 "화재사후 조사의뢰서" 제출 후 현장이 보존된 경우에만 사후조사를 거쳐 발급된다. **즉 실제 기다림은 "서류 발급"이 아니라 "화재조사 완료"에 걸리는 시간이며, 법정 표준 기간은 명시돼 있지 않다**(확인처: 소방청 화재대응조사과 044-205-7476).
→ **설계 함의:** 화면에 "서류 발급 대기 2개월"이라 쓰면 부정확하다. "화재조사 진행 중 — 완료되면 화재증명원 발급 가능"이 정확하다.



**기기 전제.** 모바일 세로가 본체. PC는 "폰 화면이 넓어지면 무엇을 펼칠까"의 관점만.

**제약(어기면 채택 불가).** ① 게임화 금지(포인트·배지·스트릭·폭죽). ② 다크패턴·거짓 진행률 금지("거의 다 왔어요" 불가). ③ 정신없는 사용자 전제 — 정보 밀도 낮게.

### ② 상위 추천 5개 상세

#### 추천 1. 상태 라벨형 태스크 리스트 — 색이 아닌 텍스트로 (GOV.UK/HMRC)
출처: https://design.tax.service.gov.uk/hmrc-design-patterns/status-tags-in-task-list-pages / https://www.tempertemper.net/portfolio/a-minimal-task-list-pattern-for-govuk

**왜 맞나.** HMRC 팀은 상태 태그에서 색 배경을 다 걷어내고 텍스트 라벨("Completed"/"Incomplete")만 남긴 버전이 사용성 테스트에서 더 잘 이해됐다고 보고했다("색 상자 사용을 뒷받침하는 발견이 없었다"). 정신없는 사용자·색각이상·저시력 모두에게 안전하다. 우리 골격의 "완료/잠김/기다리는 중" 세 상태에 그대로 맞다.

**모바일 세로 구현.** 각 할 일 카드 우측에 텍스트 상태 배지: `한 일` `잠김` `기다리는 중 · 예상 2~8주`. 색은 보조로만(잠김=회색 흐림), 의미는 항상 글자가 전달.

**PC로 넓어지면.** 세로 목록 오른쪽에 상태별 요약 패널 상시 노출(한 일 N · 지금 할 일 N · 기다리는 중 N). 탭 없이 한눈에.

#### 추천 2. 거점 스캔 타임라인으로 "지나온 길" 쌓기 (CJ대한통운)
출처: https://www.cjlogistics.com/ko/tool/parcel/tracking

**왜 맞나.** 택배 배송조회는 처리 이벤트(접수완료→간선상차→간선하차→배달출발→배달완료)가 시간순으로 아래에 쌓이며 "여기까지 왔다"를 보여준다. 우리 "한 일이 쌓인다" 연출의 검증된 국내 모델이다. 완료 체크한 일이 사라지지 않고 "한 일"로 아래에 로그처럼 쌓이면 뒤돌아볼 대상이 생긴다.

**모바일 세로 구현.** 세로 타임라인 상단=지금, 스크롤 내리면 "한 일"이 날짜와 함께 역순으로 축적. 최상단엔 "지금까지 N개 완료" 한 줄(숫자만, 배지 아님).

**PC로 넓어지면.** 왼쪽 지금 할 일, 오른쪽 "지나온 기록" 세로열 상시 병치.

**주의.** CJ 사례의 "상세위치"는 현재 좌표가 아니라 최근 처리 거점이다. 우리도 "조사 완료" 같은 상태를 실제보다 앞서 표시하지 않도록.

#### 추천 3. 마일스톤 로그 + 예상기간 병기로 대기를 진행으로 (USCIS)
출처: https://egov.uscis.gov/

**왜 맞나.** USCIS Case Status는 이벤트가 없는 긴 대기를 "Received"라는 명시적 상태로 붙잡아 둔다. 문제는 "Received"가 수주~수개월 지속돼 사용자가 침묵을 정체로 오해한다는 점이다(실무 해설들이 "상태 트래커는 실시간 작업 큐가 아니라 마일스톤 로그"라고 지적). 우리 서비스의 핵심 고통(조사 대기)과 똑같은 구조다. **해법은 상태에 예상 소요기간을 반드시 병기하는 것.**

**모바일 세로 구현.** "기다리는 중" 카드: 제목 아래 한 줄로 "화재조사 진행 중 · 보통 2~8주 · 완료되면 화재증명원 발급 가능". 진행률 %는 쓰지 않는다(거짓 진행률 금지). 대신 "지금은 소방서가 조사 중입니다 — 기다림도 과정입니다" 같은 상태 설명.

**PC로 넓어지면.** 대기 카드 옆에 "이 기간에 미리 준비할 수 있는 것"(선행 가능한 일) 패널을 펼쳐 대기를 능동 구간으로.

#### 추천 4. 갈림길 분기 = 한 화면 한 질문 (GOV.UK one thing per page)
출처: https://designnotes.blog.gov.uk/2015/07/03/one-thing-per-page/

**왜 맞나.** GDS는 "한 화면 한 가지"가 저자신감 사용자에게 쉽고, 모바일에서 잘 작동하며, 분기·루프·저장 처리에 유리하다고 다년간 검증했다. 우리 갈림길 노드(질문→가지가 실선/흐림으로 갈림)에 직접 대응한다.

**모바일 세로 구현.** 갈림길 노드에서 카드 하나에 질문 하나. 답하면 아래로 해당 가지만 실선으로 이어지고 나머지는 흐려짐.

**PC로 넓어지면.** 질문 답변 후 갈릴 가지의 미리보기를 옆 패널에 흐린 상태로 상시 노출(모바일에선 탭해야 보이던 것).

#### 추천 5. 4단계 심사 진행 (삼성화재 보험금청구)
출처: https://www.samsungfire.com/claim/P_P03_01_01_001.html

**왜 맞나.** "STEP1 청구 → STEP2 담당자 지정 → STEP3 사고조사/심사 → STEP4 확정·지급"은 불투명한 "심사 중" 대기를 눈에 보이는 단계로 쪼갠 국내 사례다. 우리의 화재조사 대기 구간을 "접수됨 → 조사관 배정 → 현장조사 → 조사완료·발급가능"으로 옮길 수 있다.

**모바일 세로 구현.** 대기 구간을 4개 하위 노드로. 현재 도달 노드까지는 실선, 이후는 흐림. 각 노드에 예상기간.

**PC로 넓어지면.** 각 단계 노드를 탭하면 나오던 "이 단계에서 무슨 일이 일어나나" 설명을 옆 패널에 상시.

### ③ 피해야 할 안티패턴

1. **게임화(포인트·배지·스트릭·폭죽).** Headspace·Duolingo류 스트릭은 놓친 날을 "실패/성격 결함"처럼 느끼게 한다는 지적이 다수(Smashing Magazine, Trophy 등). 재난 맥락에서 죄책감 유발은 치명적. Domino's가 2025년 개편에서 확정한 "placed·make·deliver·mmm!" 4단계 중 완료 축하 단계 "mmm!"도 제거 대상. → 진행감은 조용한 상태 표시로만.
2. **거짓 진행률 / 골 그래디언트 압박.** "거의 다 왔어요", 채워지는 % 바는 goal-gradient로 완료 압박을 만든다(Medium/Bootcamp 분석은 이를 "proximity를 compulsion으로 바꾸는 조작"으로 규정). 어떤 사용자가 읽어도 거짓이 아닌 문구만.
3. **속도 약속(Lemonade).** Lemonade의 'AI Jim'이 2016년 실제로 3초 만에 청구를 승인·지급한 사례를 회사가 'record'로 홍보해 널리 인용된다. 이런 속도 자랑은 실제 수주 대기와 충돌해 배신감을 준다. 노동 가시화 원리만 취하고 속도 약속은 버림. (D-019 확정 문서에 Lemonade 원문 출처 링크를 부기해 두는 것을 권장)
4. **과도한 푸시 알림.** 국민비서식 이벤트 알림은 유용하나 재난 직후 잦은 알림은 부담. 빈도 억제.
5. **색 단독 상태 표시.** 잠김/완료를 색으로만 구분하면 WCAG 1.4.1 위반이자 정신없는 사용자에게 위험.

### ⑤ 확정 골격·문구와 충돌하는 발견

각 항목: 무엇이 충돌 / 근거(등급) / 대안.

#### 충돌 1. 가로 암시선 "화재발생 ——— 회복" — 종착점을 "회복"으로 고정
- **충돌:** FEMA는 회복을 "점진적 과정"으로 규정하고 완료 시점을 약속하지 않는다[공적]. CERC는 "결과를 약속하지 말라(under promise, over deliver)"고 명시[공적]. "회복"을 선의 끝 고정점으로 그리면, 오래 낫지 않는 사용자에게 "나는 왜 도달 못 하나"라는 거짓 진행률/자책을 유발할 수 있다.
- **대안:** 끝점 라벨을 종착이 아니라 방향으로 완화("회복" 대신 "회복으로" 또는 화살표만). 현재 위치 점을 찍지 않는 현 설계는 이 위험을 이미 줄이므로 유지 권장.

#### 충돌 2. 확정 문구 "불이 꺼졌듯, 이 시간도 지나갑니다."
- **충돌 가능성(약함):** 트라우마 정보 기반 원칙상 감정을 대신 규정하는 문구는 일부 사용자에게 공허하게 읽힐 수 있음[동료심사/업계]. 다만 CERC의 "공감 먼저"와는 부합한다.
- **평가:** 이 문구는 진행률을 약속하지 않고("지나간다"는 보편 참) 은유가 부드러워 거짓 진행률·다크패턴에 해당하지 않는다. **충돌 강도 낮음 — 유지 가능.** 단 A/B로 대체 문구("여기서부터 한 걸음씩 함께 정리해요") 검증 권장.

#### 충돌 3. 할 일 카드 "최대 5장(1+4)"
- **충돌:** 급성 스트레스 시 작업기억·인지 유연성 손상 연구(Shields 2016)와 주의 터널링(Mather & Sutherland 2011)에 비추면 **5장 동시 노출은 많을 수 있다.** 최우선 1장 크게 + 나머지 접기는 좋으나, 펼쳤을 때 5장 동시 노출은 부담.
- **대안:** 기본은 최우선 1장만 펼치고 나머지 4장은 "지금 할 일 4개 더" 접힘. 숫자 상한 5는 유지하되 동시 시각 노출은 1~2장으로. one thing per page 원칙과 정합[공적].

#### 충돌 4. 금지사항("하지 마세요") 별도 고정 영역
- **충돌 가능성(약함):** GOV.UK는 부정 축약·부정 지시가 오독되기 쉽다고 경고[공적]. 고정된 금지 목록이 항상 보이면 정신없는 사용자에게 위협·불안으로 읽힐 수 있음.
- **대안:** 영역은 유지하되 (a) 현재 구간에 해당하는 금지만 노출(전체 상시 노출 지양), (b) 문구를 "~하지 마세요"보다 "지금은 ~을 미뤄두세요"처럼 이유 있는 완곡형으로. 단 안전 직결 항목(예: "타서 훼손된 전기·가스 만지지 마세요")은 명확성이 우선이므로 강한 표현 유지.

#### 충돌 5. "기다리는 중"에 예상 소요기간 표시
- **충돌:** 실제로 오래 걸리는 것은 "서류 발급"이 아니라 "화재조사 완료"다(정부24 발급 자체는 "즉시 3시간", nfds.go.kr/gov.kr). 화면에 "서류 발급 대기 2개월"이라 쓰면 부정확[공적].
- **대안:** 문구를 "화재조사 진행 중 · 완료되면 화재증명원 즉시 발급"으로. 예상기간은 범위로("보통 2~8주")+"경우에 따라 더 걸릴 수 있어요"(CERC under-promise). 법정 표준기간이 없으므로 단정 금지.

### 부록 — 압박 없는 격려 마이크로카피 실례 (요지 + 한국어 문안)

- FEMA/Ready.gov: 한 번에 한 가지씩 처리하라는 권고 → "한 번에 한 걸음씩 하세요."
- CDC CERC (Reynolds, 2016): 결과를 장담하지 말고 상황의 불확실함을 인정하되 과정에 대한 확신을 전하라 → 대기 문구의 기준선.
- USCIS 상태: "Case Was Received." (중립·사실) → "접수되었습니다." (완료 압박 없는 상태 서술)
- Headspace 복귀 프레이밍(원리만 차용): 놓친 날을 "일시적"으로, 실패로 규정하지 않음 → "오늘 못 했어도 괜찮아요. 이어서 하면 됩니다."

**마이크로카피 원칙(종합):** ① 상태를 서술하되 결과를 약속하지 않는다. ② 감정을 강요하지 않는다. ③ 부정 축약("못 해요")보다 이유 있는 완곡("지금은 미뤄두세요"). ④ 어떤 상태의 사용자가 읽어도 거짓이 아닌 문장만.

## Recommendations

**1단계 (즉시 채택 — 위험 낮고 근거 강함).**
- 상태 표시는 "색이 아니라 글자"로 통일한다(추천 1). 완료/잠김/기다리는 중을 텍스트 라벨+아이콘으로, 색은 보조로만. WCAG 1.4.1 준수.
- 대기 카드에는 **상태 문구 + 예상기간 범위 + under-promise 단서**를 항상 붙인다: "화재조사 진행 중 · 보통 2~8주 · 완료되면 화재증명원 발급 · 경우에 따라 더 걸릴 수 있어요"(추천 3, 5 / 충돌 5).
- 갈림길은 한 화면 한 질문으로 구현한다(추천 4).
- 완료한 일은 삭제하지 말고 날짜와 함께 "한 일"로 쌓아 뒤돌아볼 대상으로 만든다(추천 2).

**2단계 (확정 골격 미세조정 — D-019에서 결정 필요).**
- 카드 동시 노출을 1~2장으로 제한(충돌 3).
- 금지사항은 현재 구간 관련만 노출 + 완곡형 문구(안전 직결 항목 제외)(충돌 4).
- 가로 암시선 끝점 "회복"을 방향형으로 완화 검토(충돌 1).
- "화재조사"와 "서류 발급"을 화면 문구에서 구분(충돌 5).

**3단계 (검증).**
- 확정 문구 "불이 꺼졌듯…"과 대체안을 A/B로 정성 테스트(충돌 2).
- 화재조사 표준 소요기간을 소방청 화재대응조사과(044-205-7476)에 직접 확인해 예상기간 범위를 근거 있게 확정.

**판단을 바꿀 기준(threshold).**
- 사용성 테스트에서 대기 카드를 보고도 "지금 뭘 기다리는지 모르겠다"는 응답이 다수면 → 마일스톤을 4단계로 더 쪼갠다(추천 5).
- "회복" 끝점이 자책을 유발한다는 신호가 나오면 → 즉시 방향형으로 교체.
- 예상기간을 단정했다가 실제와 어긋나 항의가 나오면 → 범위+단서 표현으로 후퇴.

## Caveats
- **화재조사 표준 소요기간은 공식 수치가 없다.** 법정 기한이 명시돼 있지 않아 "보름~두 달", "2~8주" 등은 실무 관행 추정이다. 화면 표기 전 소방청에 직접 확인 필요.
- **해외 사례의 국내 이식 한계.** USCIS·Lemonade·Domino's는 상업/이민 맥락이라 재난 트라우마 사용자에겐 그대로 쓸 수 없고, 이 문서는 "속도 약속·게임화 제거" 등 변형 조건을 붙여 차용했다.
- **일부 인지 연구는 실험실 스트레스 유발 기반**(cold pressor, TSST 등)이라 실제 화재 트라우마와 강도·양상이 다를 수 있다. 방향성 근거로만 사용.
- **"진정 색상"은 근거가 약하다**고 명시했다. 반대로 "색을 감정 유도에 쓰라"는 제안은 채택하지 말 것.
- **본 문서는 참고자료이며 확정이 아니다.** 최종 설계 판단은 doc/design-decisions.md D-019에서 이뤄진다.
